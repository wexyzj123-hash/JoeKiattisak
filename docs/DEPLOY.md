# รายการตรวจสอบการติดตั้งและเริ่มใช้งานจริง (Deploy checklist)

ทำตามลำดับ ติ๊กทีละข้อ ข้อที่มีเครื่องหมาย 🔒 เกี่ยวกับความปลอดภัย — อย่าข้าม

> **Windows:** ใช้ชุด Zip ติดตั้ง (`python tools/build_release.py` สร้างที่ `dist/`) — แตกไฟล์แล้วดับเบิลคลิก `install.bat` → `start.bat` (อ่าน `READ_ME_FIRST.txt` ในชุด) สคริปต์ทำข้อ 1–3 ให้เอง

## 1. เตรียมโค้ด
- [ ] merge สาขา `claude/vibrant-knuth-8b04r0` เข้า `main` (ผ่าน PR)
- [ ] เครื่องเซิร์ฟเวอร์มี Python 3.10+ แล้วรัน `pip install -r requirements.txt` (Flask, waitress, Pillow, openpyxl, reportlab)
- [ ] `python -m pytest -q` ผ่านทั้งหมดบนเครื่องปลายทาง (ต้องลง `requirements-dev.txt` ก่อน)

## 1.5 พอร์ตและปุ่มเชื่อมระบบเดิม
- ถ้าเครื่องมี UT CMMS / E-Checksheet ใช้พอร์ต 5000 อยู่แล้ว **ไม่ต้องหยุดระบบเดิม** — `install.bat` หาพอร์ตว่างให้ Hub (เช่น 5001) และ Safety (5200) เอง
- ปุ่มบนหน้า Hub สำหรับเปิดระบบเดิม: ใส่ `UTCMMS_URL=http://<เครื่อง>:5000/` และ `ECHECK_URL=http://<เครื่อง>:5000/echeck/dashboard` ใน `.env` (install.bat ถามให้) หรือเพิ่มที่ Hub → ทะเบียนระบบ เลือก "เปิดลิงก์ตรง" — ปุ่มเปิดแท็บใหม่และไม่ส่ง SSO token ให้ระบบเหล่านั้น
- (ขั้นสูง) ถ้าต้องการให้ผู้ใช้เข้าผ่านพอร์ตเดียวหลัง reverse proxy ที่ตัด path ให้ตั้ง `HUB_PREFIX=/safety-hub` และ `SAFETY_PREFIX=/safety-hub/app` แล้วให้ `HUB_URL`/`SAFETY_URL` ชี้ path เดียวกัน — แอปเติม prefix ให้ลิงก์ ฟอร์ม redirect และคุกกี้เอง

## 2. ตั้งค่าความลับ 🔒
- [ ] `cp .env.example .env` แล้วแก้ค่า (ไฟล์ `.env` ห้าม commit; ความลับไม่ถูกเขียนลงฐานข้อมูล/หน้าจอ/log)
- [ ] `SSO_SECRET` ยาว ≥ 32 ตัวอักษรแบบสุ่ม และ `SERVICE_TOKEN` แบบสุ่ม — **ต้องเหมือนกันทั้ง Hub และ Safety** (ถ้ายังเป็น `change-me` ระบบไม่เริ่มทำงาน)
- [ ] `HUB_SECRET_KEY` และ `SAFETY_SECRET_KEY` ตั้งแยกกัน (คีย์ลงชื่อคุกกี้)
- [ ] `HUB_URL` / `SAFETY_URL` เป็นที่อยู่จริงที่ผู้ใช้เปิดได้ (ควรเป็น https หลัง reverse proxy)
- [ ] ตั้งเขตเวลา `SAFETY_TIMEZONE` ถ้าไม่ใช่ `Asia/Bangkok`
- [ ] (ไม่บังคับ) ย้ายที่เก็บข้อมูล: `HUB_DATABASE`, `SAFETY_DATABASE`, `SAFETY_UPLOAD_ROOT`, พอร์ต `HUB_PORT`/`SAFETY_PORT`

## 3. เปิดระบบ
- [ ] `python hub/run.py` (พอร์ต 5000) และ `python safety/run.py` (พอร์ต 5200) — ควรรันเป็นบริการ (systemd/Windows service) ให้เริ่มเองเมื่อเปิดเครื่อง
- [ ] **รัน Safety โปรเซสเดียว** — ตัวส่งแจ้งเตือนและงานประจำวันรันอยู่ในโปรเซสนั้น ถ้าจำเป็นต้องรันหลายโปรเซส ตั้ง `SAFETY_DISABLE_BACKGROUND=1` ในโปรเซสที่เหลือ
- [ ] วาง reverse proxy ที่มี https (nginx/IIS) หน้า Hub และ Safety 🔒
- [ ] เปิด Hub ครั้งแรกที่ `/setup` สร้างผู้ดูแลระบบคนแรก แล้วตั้งรหัสผ่านที่เดายาก 🔒
- [ ] ตรวจว่า Hub → ทะเบียนระบบ มีที่อยู่ Safety ถูกต้อง แล้วกดไทล์ Safety เข้าได้โดยไม่ต้องล็อกอินซ้ำ

## 4. ให้สิทธิ์ (Safety → ประเภทผู้ใช้งาน `/admin/roles`)
บทบาทที่มีอยู่แล้วไม่ถูกอัปเดตเอง ต้องติ๊กสิทธิ์ใหม่ให้ตามหน้าที่จริง (บทบาทที่สร้างใหม่หลังจากนี้ได้ค่าตั้งต้นให้)
- [ ] อุบัติเหตุ: `incident.report`, `incident.investigate`, `incident.close`
- [ ] Safety Patrol: `patrol.manage`, `patrol.perform`, `patrol.view`
- [ ] CAPA: `capa.create`, `capa.verify` (ผู้ยืนยันผลต้องไม่ใช่เจ้าของงาน/ผู้กดเสร็จ — ต้องมีผู้มีสิทธิ์นี้ ≥ 2 คน)
- [ ] รายงาน: `report.view`, `report.export`, `report.manage`
- [ ] ผู้ใช้งานแต่ละคน: กำหนดบทบาทและขอบเขตโรงงาน/แผนก (`/admin/users`)

## 5. กรอกข้อมูลหลัก (ทั้งหมดแก้ได้ในหน้า admin ไม่ต้องแก้โค้ด)
- [ ] โรงงาน → แผนก → ไลน์/กลุ่มงาน → พื้นที่เสี่ยง
- [ ] ประเภทอันตราย, แหล่งที่มา, สาเหตุอุบัติเหตุ (มีค่าตั้งต้นให้ ปรับตามบริษัท)
- [ ] เกณฑ์ความเสี่ยง (`/admin/criteria`) และระดับความรุนแรงการบาดเจ็บ (`/admin/injury-severities` — ตั้งว่าระดับไหนนับเป็น "หยุดงาน" สำหรับวันปลอดอุบัติเหตุ)
- [ ] แบบตรวจและแผนการตรวจ (`/admin/checklists`, `/admin/patrol-plans`)
- [ ] ตั้งค่า CAPA (`/admin/capa-settings`) — เปิด/ปิดการบังคับยืนยัน CAPA ก่อนปิดอันตราย (ค่าตั้งต้น: ปิด)
- [ ] กำหนดส่งรายงาน (`/admin/report-due`)
- [ ] กฎแจ้งเตือนและเวลางานประจำวัน (`/admin/notifications`; ค่าตั้งต้น 07:30, ช่วงเงียบ 22:00–06:00)

## 6. ทดลองแจ้งเตือนจริง 🔒
ตั้งค่าเฉพาะช่องทางที่ใช้ ใน `.env` (ความลับอยู่ใน environment เท่านั้น):
- [ ] Telegram: `TELEGRAM_BOT_TOKEN` (ผู้ใช้ใส่ chat id ในหน้าโปรไฟล์)
- [ ] LINE: `LINE_CHANNEL_TOKEN`
- [ ] Teams: `TEAMS_WEBHOOK_URL`
- [ ] อีเมล: `SMTP_HOST`, `SMTP_PORT`, `SMTP_TLS`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`
- [ ] รีสตาร์ต Safety แล้วสร้างรายการอันตรายทดสอบ ตรวจว่าผู้รับได้ข้อความจริงในแต่ละช่องทาง และดูสถานะคิวส่งที่ `/admin/notifications` (ล้มเหลว/ส่งไม่สำเร็จถาวรจะแสดงเหตุผล)
- [ ] ทดสอบงานประจำวัน: เพิ่มอันตรายที่ครบกำหนดเมื่อวาน แล้วดูว่ามีแจ้งเตือน "เกินกำหนด" เมื่อถึงเวลางานประจำวัน

## 7. สำรองข้อมูลและตรวจสุขภาพ
- [ ] งานประจำวันสำรองฐานข้อมูลไว้ที่โฟลเดอร์ `backups/` ข้างไฟล์ฐานข้อมูล (เก็บ 14 ไฟล์ล่าสุด) — **ให้คัดลอกออกจากเครื่องเป็นประจำ** และสำรอง `uploads/` (รูปภาพ) ด้วย
- [ ] ทดสอบกู้คืน: คัดลอกไฟล์สำรองไปเครื่องทดสอบแล้วเปิดดูได้
- [ ] ตรวจ PDF: ดาวน์โหลดรายงานเป็น PDF ว่าภาษาไทยแสดงถูกต้อง (ฟอนต์ Loma ฝังมาให้ ถ้าต้องการ Sarabun ใส่ `Sarabun-Regular.ttf`/`Sarabun-Bold.ttf` ใน `shared/assets/fonts/`)

## 8. ทดลองใช้กับผู้ใช้กลุ่มเล็ก
- [ ] เลือกผู้ใช้ 1 แผนก (หัวหน้า, จป., ผู้แจ้ง) ใช้งาน 1–2 สัปดาห์
- [ ] ผ่านครบวงจร: แจ้งอันตราย → ประเมิน → มอบหมาย → ปิด / แจ้งอุบัติเหตุ → สอบสวน → ปิด / ตรวจ Patrol → สร้าง CAPA → ยืนยันผล / ดาวน์โหลดรายงานและบันทึกการส่ง
- [ ] ทดสอบบนมือถือจริงของผู้ใช้ (ถ่ายรูปแนบ, หน้ารายการ)
- [ ] เก็บข้อเสนอแก้ไขก่อนขยายไปทุกแผนก

## ยังไม่ได้ตรวจ (ทำก่อนขึ้นระบบจริงถ้าเป็นไปได้)
- สแกนความปลอดภัยแบบ DAST (HawkScan) — ต้องมี `HAWK_API_KEY`
- ทดสอบโหลดผู้ใช้หลายคนพร้อมกันบนเครื่องจริง
