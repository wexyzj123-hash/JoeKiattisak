# AIAT Safety + Hub

ระบบบันทึกและจัดการอันตรายในโรงงาน (**Safety**) แยกเป็นเว็บของตัวเอง และเว็บกลาง (**Hub**) สำหรับเข้าสู่ทุกระบบด้วยการล็อกอินครั้งเดียว (SSO)

- Spec: `docs/superpowers/specs/2026-10-28-aiat-safety-hub-design.md`
- แผนเฟส 1: `docs/superpowers/plans/2026-10-28-phase1-hub-sso-skeleton.md`

| | Hub | Safety |
|---|---|---|
| พอร์ต | 5000 | 5200 |
| ฐานข้อมูล | `hub/data/hub.db` | `safety/data/safety.db` |
| หน้าที่ | ล็อกอิน, ผู้ใช้กลาง, ทะเบียนระบบ, ออก SSO token | ระบบความปลอดภัย (ผู้ใช้/บทบาทของตัวเอง) |

> เตรียมขึ้นระบบจริง: ดูรายการตรวจสอบ **[docs/DEPLOY.md](docs/DEPLOY.md)** (secrets → สิทธิ์ → ข้อมูลหลัก → แจ้งเตือน → ทดลองกลุ่มเล็ก)

## ติดตั้งและเปิดใช้งาน (Python 3.10+)

```bash
pip install -r requirements.txt
cp .env.example .env        # แก้ SSO_SECRET (ยาว ≥ 32 ตัวอักษร) และ SERVICE_TOKEN ให้เป็นค่าสุ่ม
python hub/run.py           # เปิดที่ http://localhost:5000
python safety/run.py        # เปิดที่ http://localhost:5200 (อีกหน้าต่างหนึ่ง)
```

1. เปิด Hub ครั้งแรกที่ `/setup` เพื่อสร้างผู้ดูแลระบบคนแรก
2. ล็อกอิน แล้วกดไทล์ **ความปลอดภัย (Safety)** — เข้า Safety ได้ทันทีโดยไม่ต้องล็อกอินซ้ำ
3. เพิ่มระบบใหม่ได้ที่ Hub → **ทะเบียนระบบ** (ไม่ต้องแก้โค้ด); จัดการผู้ใช้ที่ Hub → **ผู้ใช้**

`SSO_SECRET` และ `SERVICE_TOKEN` ต้องตรงกันทั้งสองแอป และต้องเปลี่ยนจากค่า `change-me` (ระบบไม่เริ่มทำงานถ้ายังเป็นค่าตัวอย่าง); ควรตั้ง `HUB_SECRET_KEY` / `SAFETY_SECRET_KEY` แยกด้วย; ที่อยู่ของระบบหลังเริ่มครั้งแรกแก้ได้ที่ Hub → ทะเบียนระบบ (ไม่ใช่ `SAFETY_URL`) — ผู้ใช้ Hub ที่เป็น `admin` จะได้บทบาท admin ใน Safety ตอนเข้าครั้งแรก (บทบาทหลังจากนั้นจัดการใน Safety เอง)

## ข้อมูลหลักและสิทธิ์ใน Safety (เฟส 2)

เมนูด้านข้างมี 3 กลุ่ม — ระบบข้อมูลหลัก / ข้อมูลองค์กร / ผู้ดูแลระบบ — และแสดงเฉพาะรายการที่ผู้ใช้มีสิทธิ์
- **ข้อมูลองค์กร:** โรงงาน → แผนก → ไลน์/กลุ่มงาน → พื้นที่เสี่ยง (เลือกแม่ได้เฉพาะรายการที่ใช้งานอยู่)
- **ข้อมูลหลัก:** ประเภทอันตราย, แหล่งที่มา — ทุกตารางใช้หน้าจอเดียวกัน (ค้นหา/เรียง/แบ่งหน้า 20 รายการ/เพิ่ม/แก้ไข/ปิดใช้งาน); รหัสไม่ซ้ำ (ไม่สนตัวพิมพ์เล็ก-ใหญ่) และ **ไม่มีการลบ** ใช้ "ปิดใช้งาน" เพื่อให้ประวัติเดิมยังอ่านได้
- **ประเภทผู้ใช้งาน:** สร้าง/แก้บทบาทและเลือกสิทธิ์ได้เอง (บทบาทตั้งต้น: admin, assessor, dept_head, reporter, viewer; `admin` ได้ครบทุกสิทธิ์เสมอ)
- **ผู้ใช้งาน:** ผู้ใช้ปรากฏหลังเข้าระบบผ่าน Hub ครั้งแรก — กำหนดบทบาท, ขอบเขตโรงงาน/แผนก, เปิด/ปิดใช้งาน
- อยากเพิ่มตารางข้อมูลหลักใหม่ ให้เพิ่มรายการใน `REGISTRY` (`safety/master.py`) พร้อมตารางใน `safety/schema.py`

## เกณฑ์ความเสี่ยงและทะเบียนอันตราย (เฟส 3)

- **เกณฑ์ความเสี่ยง** (ผู้ดูแลระบบ → เกณฑ์ความเสี่ยง): มาตราส่วนโอกาส/ความรุนแรง (ตั้งต้น 5×5, ปรับได้ 2-10) และระดับความเสี่ยง (ชื่อ ช่วงคะแนน สี SLA วัน ต้องอนุมัติหรือไม่) — ระดับต้องครอบคลุมทุกคะแนนพอดี ไม่ขาด ไม่ซ้อน; บันทึกทั้งฟอร์มในครั้งเดียว
- **ฟิลด์เพิ่มเติม**: ข้อมูลที่ต้องกรอกเพิ่มต่อประเภทอันตราย (ข้อความ/ตัวเลข/ตัวเลือก/วันที่/ช่องทำเครื่องหมาย) — รหัสและชนิดแก้ไม่ได้หลังสร้าง ปิดใช้งานได้ ค่าเดิมยังแสดง
- **ขั้นตอน:** แจ้ง → ประเมิน → มอบหมาย → ปิด (หรือปฏิเสธ) ทุกขั้นบันทึกประวัติแก้ไม่ได้/ลบไม่ได้ (ฐานข้อมูลบังคับ); ระดับ/คะแนน/สี **เก็บ snapshot ตอนประเมิน** แก้เกณฑ์ภายหลังไม่กระทบรายการเดิม
- **ระดับที่ "ต้องอนุมัติ"** (ตั้งต้น: สูงมาก): ผู้รับผิดชอบปิดรายการของตัวเองไม่ได้ ต้องให้ผู้อื่นปิด
- **การมองเห็น:** ผู้ที่ประเมิน/มอบหมาย/ปิด/ดูข้อมูลหลักได้ เห็นทุกรายการในขอบเขตโรงงาน/แผนกของตน; ผู้อื่นเห็นเฉพาะที่ตนแจ้ง; รายการที่มองไม่เห็นตอบ "ไม่พบ"
- **รูปถ่าย:** JPEG/PNG/WebP (ตรวจจากเนื้อไฟล์) ไม่เกิน 10 MB, ไม่เกิน 5 รูปต่อประเภท (ก่อน/หลัง), ย่อเหลือ ≤ 1600 px และล้าง EXIF/GPS; เก็บใน `safety/data/uploads/` (ตั้ง `SAFETY_UPLOAD_ROOT` เพื่อย้าย) — ต้องติดตั้ง `Pillow` (`pip install -r requirements.txt`)
- **แดชบอร์ด:** ภาพรวมดำเนินงาน (ตัวเลข แผนที่ความเสี่ยง แนวโน้ม 12 เดือน) และภาพรวมตามหน่วยงาน; ป้ายบน Hub แสดงจำนวนเปิดอยู่ + เกินกำหนด
- การแจ้งเตือนและมาสคอตเป็นเฟส 4

## การแจ้งเตือน, มาสคอต และธีม (เฟส 4)

**การแจ้งเตือน** — เขียนลงฐานข้อมูลใน transaction เดียวกับขั้นตอน (แจ้ง/ประเมิน/มอบหมาย/ปิด/ปฏิเสธ) จึงไม่หายและไม่ทำให้ขั้นตอนล้ม; ส่งจริงโดยตัวทำงานเบื้องหลัง
- **กระดิ่งในระบบ** ใช้ได้เสมอ (เมนู 🔔 การแจ้งเตือน) · **ช่องทางภายนอก**: Telegram, LINE, Teams (กลุ่มเดียวต่อกฎ), อีเมล — ผู้ใช้กรอกข้อมูลติดต่อและเลือกรับเองที่ "โปรไฟล์ของฉัน"
- **กฎ** (ผู้ดูแลระบบ → การแจ้งเตือน): เหตุการณ์ + ผู้รับ (`reporter`, `owner`, `role:<รหัสบทบาท>` เฉพาะผู้ที่ขอบเขตครอบคลุมรายการ) + ช่องทาง + จำนวนวัน; กฎ "เกินกำหนด" หลายข้อ = ยกระดับ L1–L3 (ตั้งต้น วันที่ 1 → เจ้าของ, 3 → +หัวหน้า, 7 → ผู้ดูแล+หัวหน้า)
- **ลองใหม่** 1, 5, 15, 60, 180 นาที แล้วขึ้นสถานะ "ส่งไม่สำเร็จถาวร" (ดู/ส่งใหม่/ยกเลิกได้ที่หน้าตั้งค่า) · **ช่วงเวลาเงียบ** ตั้งต้น 22:00–06:00 หน่วงเฉพาะข้อความภายนอกที่ไม่เร่งด่วน
- **งานประจำวัน** 07:30 (ตั้งได้): เตือนใกล้ครบกำหนด/เกินกำหนด + สำรองฐานข้อมูลไป `safety/data/backups/` เก็บ 14 ไฟล์ (โฟลเดอร์รูปถ่าย `safety/data/uploads/` ต้องสำรองแยกเอง)
- **ความลับอยู่ใน `.env` เท่านั้น** (ไม่แสดงในหน้าเว็บ ไม่เขียนลง log/ฐานข้อมูล): `TELEGRAM_BOT_TOKEN`, `LINE_CHANNEL_TOKEN`, `TEAMS_WEBHOOK_URL` (ต้อง https), `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASSWORD` `SMTP_FROM` `SMTP_TLS`
- ตัวส่งและงานประจำวันเริ่มพร้อม `python safety/run.py` (ตั้ง `SAFETY_DISABLE_BACKGROUND=1` เพื่อปิด เช่นรันหลายโปรเซส; `SAFETY_DELIVERY_INTERVAL` วินาทีระหว่างรอบ ตั้งต้น 30)
- **Safety ตรวจสถานะผู้ใช้กับ Hub** ทุก ~60 วินาที: ผู้ใช้ที่ Hub ปิดแล้วจะถูกออกจากระบบ; ถ้าติดต่อ Hub ไม่ได้ ระบบใช้งานต่อได้ (fail open)

**มาสคอต "น้องเอเอียต"** — ชายหนุ่มสไตล์ชิบิ หมวกแก๊ปกรมท่า AISIN ชุดฟ้าแถบสะท้อนแสง วาดเป็น SVG ใน `shared/mascot.py` (7 ท่า: `default` ยิ้มแย้ม, `confident` มั่นใจ, `thinking` ใส่ใจงาน, `celebrate` สู้ไปด้วยกัน, `earth` รักษ์โลก, `alert` ปลอดภัยไว้ก่อน (หมวกขาว), `sleeping` หลับ) — `mascot('alert', 120, decorative=True)` ซ่อนจากโปรแกรมอ่านหน้าจอเมื่อวางข้างข้อความ; ตัวอักษร AISIN วาดด้วย path ใน `shared/brand.py` (ถ้ามีไฟล์โลโก้จริงภายหลังสลับได้ที่จุดเดียว)

**ธีม "Safety 4.0"** — สว่าง (ค่าเริ่มต้น) / มืด ตามระบบหรือกดปุ่ม ◐ (จำค่าไว้ในเบราว์เซอร์), ทุกคู่สีผ่าน WCAG AA, มือถือเมนูพับเก็บ, ปิดแอนิเมชันเมื่อผู้ใช้ตั้งลดการเคลื่อนไหว

## Safety 4.0 (เฟส 5)

- **เปลือกหน้าเว็บ:** แถบข้างสีน้ำเงินมีไอคอนทุกเมนู, แถบบนมีช่องค้นหา (`/search` ค้นรหัส/หัวข้อตามสิทธิ์การมองเห็น), กระดิ่ง, ปุ่มธีม และเมนูผู้ใช้
- **หน้าหลัก `/`:** ใช้เฉพาะข้อมูลจริง — ตัวเลข 4 ช่อง (เปิดอยู่ / เกินกำหนด / ปิดเดือนนี้ / ความเสี่ยงสูง), แนวโน้ม 12 เดือน, โดนัทตามประเภทอันตราย, รายการล่าสุด, เมนูลัดตามสิทธิ์, การแจ้งเตือนล่าสุด; ไม่มีข่าว/อากาศ/e-Learning/แผนที่โรงงาน และ "วันปลอดอุบัติเหตุ" จะมาพร้อมโมดูลอุบัติเหตุ (เฟส 6)
- **ตารางบนจอแคบ:** ตาราง `.table-stack` กลายเป็นการ์ดต่อแถวต่ำกว่า 640px (ชื่อคอลัมน์ใส่โดย `theme.js`)
- **Hub:** หน้าเข้าสู่ระบบแบบสองฝั่งและหน้ารวมระบบในสไตล์เดียวกัน

### ภาพมาสคอตและโลโก้จริง

`mascot(...)` ใช้ภาพจริงจาก `shared/assets/mascot/<ท่า>.png` (พื้นโปร่งใส) ถ้ามีไฟล์ มิฉะนั้นใช้ SVG เวกเตอร์ (ตอนนี้ท่า `sleeping` ยังเป็นเวกเตอร์); โลโก้ AISIN จาก `shared/assets/brand/aisin.png` (น้ำเงิน) และ `aisin-white.png` (ขาวบนพื้นเข้ม) — เสิร์ฟผ่าน `/static/mascot/<ท่า>.png` และ `/static/brand/<ไฟล์>` แบบ whitelist
ไฟล์ชุดแรกตัดจากแผ่นมาสคอตตัวอย่าง (ความละเอียดต่ำ) — ถ้ามีไฟล์ต้นฉบับพื้นโปร่งใสให้วางทับด้วยชื่อเดิมได้เลย ไม่ต้องแก้โค้ด

## อุบัติเหตุและ Near Miss (เฟส 6)

- **ขั้นตอน:** แจ้ง (`incident.report`) → มอบหมายผู้สอบสวน → บันทึกผลสอบสวน (สาเหตุหลัก/สาเหตุราก/มาตรการ; อุบัติเหตุหยุดงานต้องระบุจำนวนวันหยุด) → ปิดรายการ (`incident.close`) หรือปฏิเสธ — ผู้ที่เคยเป็นผู้สอบสวนปิดรายการเองไม่ได้ (four-eyes) ทุกขั้นเก็บประวัติแบบเพิ่มอย่างเดียว และใช้ optimistic lock
- **Near Miss** ประเมิน "โอกาส × ความรุนแรงที่อาจเกิด" ด้วยเกณฑ์ความเสี่ยงเดียวกับรายการอันตราย; **อุบัติเหตุ** เลือกระดับการบาดเจ็บ (ค่าเริ่มต้นตามมาตรฐานโรงงานทั่วไป: ทรัพย์สินเสียหาย / ปฐมพยาบาล / รักษาพยาบาล / หยุดงาน / ทุพพลภาพถาวร / เสียชีวิต — แก้ได้ที่ `/admin/injury-severities`)
- **ข้อมูลส่วนบุคคล:** ชื่อ/รหัสพนักงานของผู้เกี่ยวข้องเห็นได้เฉพาะผู้สอบสวน ผู้ปิดรายการ ผู้ดูแลระบบ และผู้แจ้งรายการนั้น — ไม่ปรากฏในรายการ ค้นหา แดชบอร์ด สถิติ การแจ้งเตือน หรือประวัติ (ประวัติเก็บแค่จำนวนคน)
- **"วันปลอดอุบัติเหตุ"** = จำนวนวันนับจากอุบัติเหตุ "หยุดงาน" ครั้งล่าสุด (ระดับที่ติ๊ก "นับเป็นหยุดงาน"; ไม่นับรายการที่ถูกปฏิเสธ) ตามขอบเขตโรงงาน/แผนกของผู้ดู; ยังไม่มีอุบัติเหตุหยุดงานจะแสดงข้อความแทนตัวเลข; หน้า `/incidents/stats` แสดงสถิติรายเดือน/ตามระดับ/ตามพื้นที่
- **สิทธิ์ใหม่:** `incident.report`, `incident.investigate`, `incident.close` — บทบาทที่สร้างใหม่ได้ค่าเริ่มต้น (ผู้ประเมิน = ครบ, หัวหน้า = แจ้ง+สอบสวน, ผู้แจ้ง = แจ้ง) **ฐานข้อมูลเดิมไม่ถูกเปลี่ยนบทบาทที่มีอยู่** ผู้ดูแลระบบต้องเปิดสิทธิ์ให้ที่ `/admin/roles`
- **การแจ้งเตือน:** กฎใหม่ 3 เหตุการณ์ (`incident_reported/assigned/closed`) แก้ได้ที่ `/admin/notifications`; ตารางกฎเก่าถูกสร้างใหม่อัตโนมัติโดยคงรหัสและค่าที่แอดมินแก้ไว้

### เวลาและการปรับระดับความรุนแรง (ส่วนเสริมเฟส 6)

- **โซนเวลา:** ทั้ง Safety และ Hub ตั้งโซนเวลาของโปรเซสเป็น `Asia/Bangkok` ตอนเริ่ม (เปลี่ยนได้ด้วย `SAFETY_TIMEZONE`) จึงไม่ขึ้นกับการตั้งค่าของเครื่อง — ใช้กับ `datetime.now`, `localtime` ของ SQLite และเวลาในบันทึก
- **ปรับระดับการบาดเจ็บหลังแจ้ง:** ผู้สอบสวน (`incident.investigate`) ปรับได้ที่หน้ารายละเอียด (ใช้ได้กับรายการที่ปิดแล้ว ไม่ใช้กับที่ปฏิเสธ/Near Miss) ต้องระบุเหตุผล และจำนวนวันหยุดงานถ้าเป็นระดับหยุดงาน — บันทึกในประวัติ (รหัสระดับเดิม/ใหม่) และตัวนับ "วันปลอดอุบัติเหตุ" ตามระดับใหม่ทันที
- **ฟอร์มแจ้งใหม่:** ระบุผู้เกี่ยวข้องได้ 20 คน (แสดง 5 ช่องแรก ที่เหลืออยู่ใน "เพิ่มผู้เกี่ยวข้องอีก")

## Safety Patrol และ CAPA (เฟส 7)

- **แบบตรวจ** (`/admin/checklists`, สิทธิ์ `patrol.manage`): รายการตรวจแบ่งเป็นหมวด ตอบ ผ่าน/ไม่ผ่าน/ไม่เกี่ยวข้อง กำหนดน้ำหนักคะแนน (1–10) และ "ต้องแนบรูปเมื่อไม่ผ่าน" ได้; ลบไม่ได้ (ปิดใช้งานแทน)
- **แผนการตรวจ** (`/admin/patrol-plans`): ผูกแบบตรวจกับพื้นที่ + ความถี่ รายวัน/สัปดาห์/เดือน + ผู้ตรวจประจำ (ไม่บังคับ); ครบรอบนับจากรอบที่ส่งแล้วล่าสุด (สิ้นเดือน/ปีอธิกสุรทินถูกต้อง) พลาดหลายรอบนับเป็นสถานะเดียว; ตัวเตือนประจำวันแจ้ง `patrol_due` / `patrol_overdue` (แก้กฎได้ที่ `/admin/notifications`)
- **รอบตรวจ** (`/patrols`, สิทธิ์ `patrol.perform`): เริ่มรอบ → ตอบทีละข้อ (ปุ่มใหญ่สำหรับมือถือ) แนบรูป → ส่ง; รอบตรวจคัดลอกรายการตรวจไว้ตอนเริ่ม (แก้แบบตรวจทีหลังไม่กระทบ); **เมื่อส่งแล้วแก้ไม่ได้** ทั้งจากหน้าจอและระดับฐานข้อมูล (ทริกเกอร์); ข้อที่ไม่ผ่านและต้องมีรูปจะส่งไม่ได้ถ้าไม่มีรูปของข้อนั้น
- **ข้อไม่ผ่านกดครั้งเดียว** สร้างรายการอันตราย (คัดลอกรูปให้) หรือ CAPA — กดซ้ำได้ตัวเดิม ไม่ต้องมีสิทธิ์แจ้งอันตราย/สร้าง CAPA แยกต่างหาก
- **CAPA** (`/capas`): เปิด → กำลังทำ → เสร็จ → ยืนยัน (หรือยกเลิก/ตีกลับ); เจ้าของงานเป็นใครก็ได้ (ไม่ต้องมีสิทธิ์); ผู้ยืนยันต้องมีสิทธิ์ `capa.verify`, **ต้องไม่เคยเป็นเจ้าของ (รวมที่โอนออกแล้ว) และไม่ใช่ผู้ที่กดว่าเสร็จ**; ตั้งวันตรวจประสิทธิผลได้ แล้วบันทึกได้ผล/ไม่ได้ผลครั้งเดียว; เตือนใกล้ครบ/เกินกำหนด ยกระดับ L1–L3 (วันที่ 1/3/7)
- **ประตูปิดรายการ:** `/admin/capa-settings` — เมื่อเปิด การปิดรายการอันตราย/อุบัติเหตุจะถูกปฏิเสธจนกว่า CAPA ของรายการนั้นจะยืนยันครบ (ไม่นับที่ยกเลิก; รายการอันตรายที่มาจากข้อตรวจนับ CAPA ของข้อนั้นด้วย); **ค่าเริ่มต้นปิด**; ตรวจในธุรกรรมเดียวกับการปิดจึงไม่มีช่องให้แทรก
- **สิทธิ์ใหม่:** `patrol.manage/perform/view`, `capa.create/verify` — บทบาทที่สร้างใหม่ได้ค่าเริ่มต้น (ผู้ประเมิน: perform+view+create+verify, หัวหน้า: view+create) **บทบาทเดิมในฐานข้อมูลไม่ถูกแก้** ผู้ดูแลระบบต้องเปิดสิทธิ์ที่ `/admin/roles`
- **หน้าหลัก:** ตาราง "การตรวจความปลอดภัยล่าสุด" (ข้อมูลจริงตามสิทธิ์) และการ์ด "CAPA เกินกำหนด"

## รายงานและสถิติ (เฟส 8)

- **รายงาน 4 แบบ** ที่ `/reports`: รายงานประจำเดือนตามแผนก, สรุปประจำปี, สถิติอุบัติเหตุ, สถานะ CAPA — คำนวณจากข้อมูลจริงตามขอบเขตโรงงาน/แผนกของผู้ใช้ (แผนกนอกขอบเขต → 404) ไม่มีชื่อผู้บาดเจ็บหรือข้อมูลส่วนบุคคลในรายงานใด ๆ
- **ส่งออก Excel (openpyxl) และ PDF (reportlab)** — หน้าจอ Excel และ PDF ใช้โครงสร้างข้อมูลเดียวกัน; ข้อความใน Excel ที่ขึ้นต้นด้วย `= + - @` ถูกเขียนเป็นข้อความ (กัน formula injection)
- **ฟอนต์ไทยใน PDF** ฝังอยู่ใน `shared/assets/fonts/` (ไม่ดาวน์โหลดตอนใช้งาน): ใช้ Sarabun (OFL) ถ้ามีไฟล์ `Sarabun-Regular.ttf`/`Sarabun-Bold.ttf` ไม่เช่นนั้นใช้ Loma (GPL-2+ พร้อมข้อยกเว้นฟอนต์ — ฝังในเอกสารได้) ซึ่งแปลงจาก OpenType เป็น TrueType ด้วย `tools/otf_to_ttf.py` (ดู `LICENSE.txt` ในโฟลเดอร์ฟอนต์) ถ้าไม่พบฟอนต์ ระบบแจ้งและส่งออก Excel ได้ตามปกติ
- **กำหนดส่งรายงาน** ที่ `/admin/report-due` (`report.manage`): รายเดือน = ส่งรายงานของเดือนก่อนในวันที่กำหนดของเดือนถัดไป, รายปี = ส่งรายงานของปีก่อน; กำหนดที่ผ่านไปก่อนวันที่สร้างไม่ถูกนับค้างส่ง; "บันทึกว่าส่งแล้ว" เป็นบันทึกเพิ่มได้อย่างเดียว (ทริกเกอร์กันแก้/ลบ, งวดเดียวส่งได้ครั้งเดียว)
- **การเตือน** ใช้กฎเดิมที่ `/admin/notifications`: `report_due_soon` (ตั้งต้น 3 วันก่อนถึงหัวหน้าแผนก) และ `report_overdue` (1 วัน → หัวหน้าแผนก, 3 วัน → ผู้ประเมิน) ผ่านงานประจำวัน; งวดที่ส่งแล้วไม่ถูกเตือน; หน้านี้แก้จำนวนวันของกฎ CAPA/ตรวจ/รายงานได้แล้ว (เดิมบันทึกไม่ได้)
- **สิทธิ์ใหม่:** `report.view`, `report.export`, `report.manage` — ตั้งต้นให้เฉพาะบทบาทที่สร้างใหม่ (ผู้ประเมินครบทั้งสาม, หัวหน้าหน่วยงาน view+export); บทบาทเดิมให้สิทธิ์เองที่ `/admin/roles`
- **อัปเกรดจากเฟส 7:** รันแล้วสร้างตารางใหม่และเพิ่มกฎเตือน 3 ข้อให้เองครั้งเดียว (รวม 26 กฎ) โดยไม่แตะข้อมูล/กฎที่แก้ไว้
